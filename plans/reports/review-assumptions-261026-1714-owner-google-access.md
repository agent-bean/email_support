## High — A delayed disconnect revoke can invalidate a newer successful consent

- Plan: `phase-03-google-connection-and-verification.md:39–42,58–60`. Consent may advance generation and save a replacement connection while disconnect's HTTP revoke is pending. The stated fence at line 59 protects only the late metadata write.
- Repository evidence: `docs/04-code-standards.md:26` requires external HTTP outside transactions; `docs/02-system-architecture.md:59–60` defines separate login/connection responsibilities and server-held refresh credentials. The project's research also identifies project-wide revocation at `plans/reports/researcher-261026-1714-google-connection.md:46`. Current storage offers no preexisting remote-operation fencing mechanism to reuse (`apps/backend/src/email_support/storage/postgres/persistence/database.py:16–20` is only a session factory).
- Provider verification: Google says revoke invalidates issued tokens for the project's clients, and propagation can be delayed. [Google web-server OAuth revocation](https://developers.google.com/identity/protocols/oauth2/web-server#tokenrevoke), inspected 2026-10-26.
- Concrete failure: tab A commits disconnected/purged generation N and starts revoke; tab B completes explicit reconnect at N+1; the older revoke reaches Google afterward. The database remains `connected` at N+1 because the old response's CAS fails, but the replacement grant has been revoked remotely. Local generation fencing cannot fence Google's project-level operation. A timeout also leaves uncertainty after the HTTP caller has returned.
- Minimal fix: specify durable revoke-in-progress/unknown eligibility on the existing connection row. Prevent new consent from becoming usable while a preceding revoke can still affect it; show the existing actionable unknown/manual-removal flow. After an unresolved revoke, require confirmed cleanup before completing reconnect. Add one deterministic delayed-revoke-versus-reconnect test; no new service, worker or infrastructure is needed. Controller should choose exact recovery wording rather than implying that a generation CAS protects the remote grant.
