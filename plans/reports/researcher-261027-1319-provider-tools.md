## Recommendation

Implement small typed adapters and one application-owned tool registry/execution boundary. Keep model schemas, argument validation, role permissions, provider response normalization, retries, and trace records in the application. Prefer direct async HTTP over adding LangChain provider wrappers for this slice: existing project architecture gives LangGraph orchestration ownership and requires deterministic typed tool functions, while OpenAI-compatible chat completions, OpenRouter embeddings, and Tavily search are narrow JSON HTTP contracts. Do not create a generic plugin framework or expose provider payloads as application contracts.

Issue ownership remains distinct: #32 owns the eval dataset/runner and quality measures; #9 owns provider adapters, callable tools, execution evidence and contract tests; #13 consumes those tools and traces in the briefing workflow. Implement all #9 acceptance criteria here, including an opt-in live smoke, rather than treating provider-specific unknowns as a reason to defer adapters or smoke criteria.

## Evidence and compatibility

- OpenAI’s function-calling contract returns tool names plus JSON-encoded arguments; it explicitly requires application-side validation because arguments may be malformed or include parameters absent from the schema. Structured output uses JSON Schema with `strict`, but only a supported schema subset; a schema-shaped answer still requires Pydantic validation. The Chat Completions reference documents `tool_calls`, `finish_reason`, token usage, and optional streamed usage. [Function calling](https://platform.openai.com/docs/guides/function-calling), [structured outputs](https://platform.openai.com/docs/guides/structured-outputs), [Chat Completions API reference](https://platform.openai.com/docs/api-reference/chat/object).
- OpenRouter’s tool guide describes the client-side loop: inspect `finish_reason`, execute tools, append results, and request the next completion. It also documents disabling parallel calls. Its structured output page says support is limited to compatible models. Its embeddings API accepts text/list input and a model, returns vectors and may return token usage. These establish generic documented API behavior, not the configured gateway’s behavior. [OpenRouter tool calling](https://openrouter.ai/docs/guides/features/tool-calling), [structured outputs](https://openrouter.ai/docs/guides/features/structured-outputs), [embeddings](https://openrouter.ai/docs/api/api-reference/embeddings/create-embeddings).
- Tavily exposes `POST https://api.tavily.com/search` with bearer authentication, bounded `max_results`, optional raw content and optional usage. Keep the default request minimal: basic search, small result cap, no answer generation, images, or raw full-page content unless the role contract specifically needs it. Normalize results to URL/title/snippet/published date where present; publisher dates may be absent. [Tavily Search API](https://docs.tavily.com/documentation/api-reference/endpoint/search).
- The project is Python 3.13-only and currently pins `httpx2>=2.16,<3`, not legacy `httpx`; Google integrations already use its async client, fixed provider endpoints, timeouts and `follow_redirects=False`. Current OpenAI Python SDK documentation says the SDK uses HTTPX2, supports Python 3.13, and accepts custom HTTPX2 clients. Thus a direct HTTP adapter can reuse the existing dependency and an SDK is also compatible in principle. However, Tavily’s official async SDK example specifically accepts a standard `httpx.AsyncClient`; adding that SDK would introduce a second HTTP stack unless interoperability is proven. Direct REST adapters avoid the additional dependency and preserve exact timeout/body/redirect policy. Revisit SDK use only if its maintained functionality materially removes code and its HTTPX2 interop passes dependency and contract checks. [Project dependency manifest](../../apps/backend/pyproject.toml), [OpenAI SDK HTTPX2 migration](https://github.com/openai/openai-python/blob/main/httpx2.md), [Tavily Python SDK](https://github.com/tavily-ai/tavily-python).
- OWASP warns that redirects can bypass URL validation, domain allowlisting alone does not stop DNS rebinding, and validation must apply to the IP actually used for connection. For arbitrary public web fetch, block non-global IPv4/IPv6 destinations, reject non-HTTPS schemes, userinfo and nonstandard ports, and disable automatic redirects. If redirects are required, follow manually with a small hop cap and repeat full URL/DNS checks on every hop. DNS validation followed by a separate unconstrained HTTP lookup is insufficient; pin the vetted address in the transport or enforce a network egress boundary. [OWASP SSRF Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html), [OWASP Webhook SSRF guidance](https://cheatsheetseries.owasp.org/cheatsheets/Webhook_Security_Cheat_Sheet.html).

## Concrete safe-fetch route

HTTPX2 has a documented request extension for this exact operation: provide an explicit IP in the request URL, set `Host` to the original hostname, and set `extensions={"sni_hostname": original_hostname}`. Its docs say this connects to the literal address while using the original hostname for the Host header and TLS certificate hostname verification. The version resolved by `uv.lock` is 2.16.0, whose tagged docs and HTTPCore2 source show the same hook: the connection reads `sni_hostname`, opens TCP to the URL origin host, and passes the override as TLS `server_hostname`. This avoids writing a custom socket or proxy transport. HTTPCore2 also exposes custom network backends, but they are unnecessary here. [HTTPX2 current request-extension docs](https://pydantic.dev/docs/httpx2/advanced/extensions/), [HTTPX2 v2.16.0 tagged extension docs](https://github.com/pydantic/httpx2/blob/v2.16.0/docs/advanced/extensions.md), [HTTPX2 v2.16.0 HTTPCore2 async connection](https://github.com/pydantic/httpx2/blob/v2.16.0/src/httpcore2/httpcore2/_async/connection.py), [HTTPCore2 network backends](https://pydantic.dev/docs/httpx2/httpcore2/network-backends/).

Recommended route for each fetch:

1. Parse and canonicalize once with `httpx2.URL`; accept HTTPS on port 443 only, reject userinfo, fragments if not needed, malformed hostnames and unsupported IP-literal forms. Do not use string-prefix hostname checks.
2. If the URL host is a literal IP, validate it and use that address directly. Otherwise use `dns.asyncresolver.Resolver().resolve_name(host, family=socket.AF_UNSPEC, search=False, lifetime=small_dns_budget)` to obtain both A and AAAA answers under one resolver lifetime and without search-suffix expansion. This is async DNS with an explicit timeout and normal OS resolver configuration. Add `dnspython` as a direct dependency if application code imports it; it is currently only transitive through `email-validator` in the lock. Reject the whole answer set if empty or if any returned address is not globally routable; do not pick only the public member of a mixed public/private answer set. [dnspython async resolver](https://dnspython.readthedocs.io/en/stable/async-resolver-class.html), [Python asyncio DNS note](https://docs.python.org/3/library/asyncio-eventloop.html#dns).
3. For each accepted candidate (fallback only among already validated IPs), form a URL using that literal IP (bracket IPv6) with the original path/query, send `Host: original-host`, and pass `extensions={"sni_hostname": original-host}`. Keep normal TLS verification enabled. Force HTTP/1.1 (HTTPX2 default) for the explicit Host-header path; do not enable HTTP/2 where authority handling could differ. Create an isolated client for the request with `trust_env=False`, no configured proxy, `follow_redirects=False`, strict connect/read/write/pool timeouts and no keep-alive reuse. The connection target is the IP literal, so HTTPX2 has no second hostname lookup to rebind; environment proxy variables cannot send the hostname elsewhere. The core request shape is:

   ```python
   async with asyncio.timeout(total_budget):
       async with httpx2.AsyncClient(
           trust_env=False,
           follow_redirects=False,
           timeout=httpx2.Timeout(
               connect=connect_budget,
               read=read_budget,
               write=write_budget,
               pool=pool_budget,
           ),
           limits=httpx2.Limits(max_keepalive_connections=0),
       ) as client:
           async with client.stream(
               "GET",
               ip_literal_url_with_original_path_and_query,
               headers={"Host": original_host, "Accept-Encoding": "identity"},
               extensions={"sni_hostname": original_host},
           ) as response:
               ...  # reject 3xx and stream/count under byte cap
   ```

   Treat this as the supported transport shape to spike against the locked version, not as tested application code. [HTTPX2 client/API reference](https://pydantic.dev/docs/httpx2/api/api/), [HTTPX2 client configuration](https://pydantic.dev/docs/httpx2/advanced/clients/).
4. Return redirects as a typed source-unavailable outcome (`redirect_blocked`); do not follow them. Redirects are not necessary for the initial research contract, and rejecting them avoids another validation/fetch loop. A caller may retain the original search result URL and snippet as evidence, clearly marking that page content was unavailable. This meets the safety criterion truthfully without silently pretending to have fetched the redirected page. If a later requirement needs redirects, add a separate bounded loop that accepts only a `Location` parsed against the prior URL, re-runs steps 1–3 for each hop, caps hops (for example, three), and never forwards credentials/cookies.
5. Request `Accept-Encoding: identity`, reject unexpected `Content-Encoding`, inspect `Content-Length` as an early rejection only, and still stream/count every raw byte under the body cap. Decode text only after the cap has been enforced. Enforce a single total deadline around resolution, connection and body streaming; cancellation closes the HTTPX2 stream context. HTTPX2 documents `AsyncClient.stream` and `Response.aiter_raw()`/`aiter_bytes()` for bounded streaming. [HTTPX2 async streaming](https://pydantic.dev/docs/httpx2/guides/async/).

This route provides an explicit pinned-address mechanism in the exact locked version’s documented implementation. I could not import `httpx2` from the workspace’s base Python (module absent) and did not enter the protected `.venv` or install packages; the report therefore identifies the supported route from `uv.lock` and tagged upstream source, while the application-specific compatibility spike remains unexecuted.

### Compatibility spike pass/fail contract

Before making the fetcher a production callable, run a small isolated spike against the locked HTTPX2/HTTPCore2 versions (the spike is implementation work, not completed research evidence):

- **PASS — connection pinning:** with a deterministic test resolver returning a fixture address, the HTTPX2 request URL/transport connects to that IP and never performs another name lookup; the request preserves the original host in `Host` and TLS SNI, and a local TLS fixture with a matching SAN verifies successfully. The local fixture bypasses the production public-IP check only in this low-level transport compatibility spike; a separate pure policy test must prove loopback/private fixture addresses are rejected by the production validator.
- **PASS — proxy and pool isolation:** a configured environment proxy is ignored (`trust_env=False`); no proxy or hostname-based connect occurs; no connection is reused across differing original host/SNI values.
- **PASS — bounded operations:** resolver `lifetime` expires the DNS operation at its configured budget; connect/read/pool and total deadlines expire; cancellation exits the stream context; raw streaming stops once the byte cap is exceeded even with absent/false Content-Length.
- **PASS — redirect behavior:** a 3xx response is returned without a second request and maps to `redirect_blocked`; source result preserves only safe metadata and reports page content unavailable.
- **FAIL / do not ship:** any connection does not target the validated IP, TLS verification does not use the original host, environment proxy can intercept, a redirect is followed, data is buffered before the cap, timeout/cancellation leaves an unbounded operation, or the locked HTTPX2 extension signature is incompatible. A failure must be resolved by a version-compatible HTTPX2 adapter or a narrowly scoped raw async socket/TLS implementation only if no supported transport hook can satisfy the same checks; it must not be downgraded to a DNS pre-check.

## Minimal implementation contracts

1. **Provider contracts and configuration.** Define typed request/result contracts for chat completions/tool calls, embeddings, search results, and normalized provider usage. Read endpoint/model/credential settings from private runtime configuration; validate at startup and never put endpoint secrets into model context, reports, or normal logs. Keep model IDs configurable strings rather than enums. The actual gateway URL, capabilities, and approved embedding model are deployment facts that require authorized configuration and smoke evidence; do not invent them in public docs.
2. **Tool registry and permissions.** Use closed `ToolName` identities plus metadata containing input/output schema and callable implementation. Pydantic tool args/results use `extra="forbid"`; convert provider JSON to `unknown`/object, validate once, and reject unknown IDs, malformed args, invalid output, or a call outside that role’s explicit allowlist before invocation. Expose only read-only research tools in this issue. No send, approval, or knowledge-promotion callable belongs in the registry; provider `tool_choice` and model schema are not authorization.
3. **Execution boundary.** One async executor owns dispatch, deadlines, retry policy, safe error categories, and evidence. Categorize at least invalid request/schema, authentication/permission, rate limit, timeout/cancelled, provider unavailable, malformed response, and tool failure; keep detail safe for traces. Use a per-attempt timeout and a total deadline, bounded attempts/backoff with jitter and `Retry-After` where valid. Retry only transient failures while budget remains; never retry validation/auth failures. Treat ambiguous post-send timeout as an unknown upstream outcome (avoid blind repeated inference/cost). Propagate `asyncio.CancelledError`; do not convert cancellation to ordinary failure. Keep provider calls async and outside database transactions.
4. **Bounded source fetch.** Implement the explicitly required application-controlled fetch path only for source URLs needed beyond Tavily snippets, using the literal-IP URL plus HTTPX2 `sni_hostname` extension detailed above. Enforce HTTPS/443, reject non-global answers, bypass ambient proxies, disable redirects, apply a deadline and stream caps, and return an honest source-unavailable outcome on blocked redirects. This is needed even for Tavily-returned URLs because search results are untrusted. Run the compatibility spike before opening this fetcher to the workflow.
5. **Evidence and privacy.** Every tool execution carries existing workflow `run_id`, role identity, closed tool identity, start/duration, success or normalized failure, provider/model where applicable, and optional provider usage/cost. Represent absent usage as `None`/unknown, never `0`. Do not log prompts, full email bodies, returned page contents, credentials, raw headers, or unrestricted tool arguments. Bound and redact error text. Tracing provides evidence; it must not alter tool permissions or approval decisions.

## Risks and unresolved facts

- OpenAI-compatible request syntax is not evidence that the selected custom gateway supports tools, strict structured outputs, returned usage, embedding endpoints, or the assumed error/timeout semantics. The smoke is a required evidence gate for these claims.
- The SSRF-safe fetch route is documented and corroborated in the locked HTTPX2/HTTPCore2 2.16.0 source, but it has not yet been exercised by an application-specific compatibility spike. The spike pass/fail contract above is required; do not replace it with a preflight-only DNS check.
- No target gateway URL, supported model identifiers, token/cost policy, or fetch content-type/byte budgets are established in the public docs/issues examined. Read approved private runtime settings during implementation, then make the minimal explicit contract. These values affect configuration, not the API architecture.
- LangChain wrappers offer ready-made model/tool abstractions, but add dependency and version/model compatibility surfaces while bypassing none of the application's required typed authorization, fetch policy, redaction, retry, and trace logic. Direct typed adapters rank first for this scope. OpenAI SDK is a reasonable alternative for chat/embeddings only if its endpoint and HTTPX2 behavior pass the same tests; direct Tavily REST remains simplest.
